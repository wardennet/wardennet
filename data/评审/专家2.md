## 一、spec.md 建议修改

### 1. 第1节「技术栈」补充对象存储选型

当前描述：
> 数据库：PostgreSQL（主库，精简特征）、Redis（缓存/限流/版本号）、对象存储/本地文件（原始证据片段）

建议修改为明确选型，避免开发时反复决策：
> 数据库：PostgreSQL（主库，精简特征）、Redis（缓存/限流/版本号）、对象存储（原始证据片段，优选阿里云OSS/腾讯云COS/AWS S3，本地开发环境可用MinIO模拟）

### 2. 第5.3节「优先级链」逻辑顺序微调

当前描述：
> 系统全局白名单 > 租户私有白名单 > Agent本地配置白名单 > L3 > L2 > L1 > 云端下发黑名单 > Agent本地配置黑名单 > Agent CLI手动拉黑

这里存在一个小问题：**CLI手动拉黑是用户主动行为，优先级应该最高**，否则用户执行 `wardenet blocklist add` 后发现不生效（因为系统全局白名单包含了该IP），体验很差。

建议修改为：
> **Agent CLI 手动拉黑 > 系统全局白名单 > 租户私有白名单 > Agent 本地配置白名单 > L3 > L2 > L1 > 云端下发黑名单 > Agent 本地配置黑名单**

说明：CLI手动拉黑是用户明确指令，即使是白名单IP也应该被临时覆盖（可加 `--force` 参数）。白名单用户主动拉黑自己的IP属于管理行为，优先级最高符合直觉。

### 3. 第5.6节「白名单豁免约束」补充防滥用机制

当前描述完整，但可以补充一点：
> 建议增加：单个租户白名单IP数量上限（默认1000个），避免白名单被滥用为“永久免封金牌”导致防护失效。

### 4. 第7节「禁止实现范围」补充一条

建议新增：
> 12. 不绕过白名单内测准入机制；不通过环境变量/配置文件隐藏开关绕过海外IP拦截。

### 5. 第2.2节「数据校验规则」补充一条

当前描述：
> 客户端上报证据云端全量二次校验（签名、来源agent_id、租户绑定、IP格式、时间戳偏差）。

建议修改为包含一条降级策略的说明：
> 客户端上报证据云端全量二次校验（签名、来源agent_id、租户绑定、IP格式、时间戳偏差）。校验失败时，**仅丢弃该条证据，不影响其他证据的上报与存储**。

## 四、给“AI + Go”组合的几条实战建议
既然你打算用 AI 来写 Go，我给你三条落地建议，帮助 AI 写出更高质量的 Go 代码：

1. 提示词里写明“按 Go 官方风格，用 gofmt 格式化”
AI 生成 Go 代码默认风格就是对的，但你可以补充一句：“遵循 Effective Go 和 Go 官方代码风格”，产出的代码会更规范。

2. 让 AI 帮你写测试，再用 go test -race 检查
这是 Go 最强大的能力之一。AI 生成代码后，让 AI 同时生成对应的表驱动测试，然后用 go test -race 跑一遍。数据竞争在 Go 里是可检测的，在 Python 里只能靠猜。

3. 错误处理不要偷懒
AI 有时候会写出 _ = someFunc() 这种忽略错误的代码。在 Code Review 时（或者直接在提示词里强调）：“所有 error 必须显式处理或向上传递，禁止忽略错误返回值。”
