## 二、v1.0 功能增强清单

### 2.1 P0 级增强（必须补齐）

#### 2.1.1 端口扫描检测模块

**现状**：只检测 HTTP 日志，无法感知 TCP 端口扫描（nmap SYN 扫描）

**目标**：新增 `portscan` 模块，检测网络层侦察行为

**需求规格**：

| 项目 | 说明 |
|------|------|
| 数据源 | netfilter 日志（`iptables -I INPUT -j LOG`）或 eBPF 探针 |
| 检测逻辑 | 三档窗口统计单IP访问的不同端口数 |
| 触发阈值 | 5s内>5个端口 / 30s内>15个端口 / 120s内>40个端口 |
| 动作 | 自动封禁，与现有黑名单合并 |
| 配置项 | 端口阈值、窗口大小、是否启用 |

**接口设计**：

```go
// internal/portscan/config.go
type PortScanConfig struct {
    Enabled      bool          `yaml:"enabled"`
    LogPath      string        `yaml:"log_path"`      // netfilter日志路径
    Windows      []PortWindow  `yaml:"windows"`
    BlockTTL     int           `yaml:"block_ttl"`     // 封禁时长
}

type PortWindow struct {
    Size    int `yaml:"size"`     // 窗口秒数
    MaxPorts int `yaml:"max_ports"` // 最大不同端口数
}
```

**YAML 配置示例**：

```yaml
port_scan:
  enabled: true
  log_path: /var/log/portscan.log
  block_ttl: 3600
  windows:
    - size: 5
      max_ports: 5
    - size: 30
      max_ports: 15
    - size: 120
      max_ports: 40
```

#### 2.1.2 请求体攻击检测

**现状**：只检测 URL 路径中的攻击模式，不解析请求体（POST body、JSON、XML）

**目标**：对请求体中的攻击载荷进行检测

**需求规格**：

| 项目 | 说明 |
|------|------|
| 支持格式 | `application/x-www-form-urlencoded`、`application/json`、`multipart/form-data`、`application/xml` |
| 检测内容 | SQL注入、XSS、RCE、XXE、SSRF |
| 数据源 | Nginx 日志中的 body 记录（需配置 `$request_body`）或通过插件获取 |
| 性能要求 | 解析和检测总耗时 < 5ms |

**设计要点**：

```go
// internal/detector/body_scanner.go
type BodyScanner struct {
    maxBodySize int64  // 最大解析大小，默认 1MB
    patterns    []Pattern
}

// 扫描策略：
// 1. 根据 Content-Type 选择解析器
// 2. JSON: 解析为 map[string]interface{}，递归扫描所有 string 值
// 3. Form: 直接扫描所有字段值
// 4. XML: 检测 <!DOCTYPE、ENTITY 等XXE特征
// 5. Multipart: 检测文件名、文件内容
```

**YAML 配置**：

```yaml
detector:
  body_scan:
    enabled: true
    max_size: 1048576  # 1MB
    content_types:
      - application/json
      - application/x-www-form-urlencoded
      - multipart/form-data
      - application/xml
    # 文件上传检测
    file_upload:
      blocked_extensions:
        - .php
        - .jsp
        - .asp
        - .aspx
        - .phtml
        - .htaccess
      blocked_mime_types:
        - application/x-php
        - application/x-jsp
        - text/x-php
```

#### 2.1.3 IDOR/BOLA 越权检测

**现状**：无法从流量层面检测越权访问

**目标**：通过资源访问模式分析，检测可能的 IDOR 攻击

**需求规格**：

| 项目 | 说明 |
|------|------|
| 检测原理 | 同一IP在时间窗口内访问大量不同资源ID |
| 实现方式 | 构建资源访问基线，统计不同资源ID数量 |
| 触发条件 | 60s内访问 > 20 个不同用户ID / 订单ID 等 |
| 配置项 | 资源ID模式（正则）、窗口大小、阈值 |

**设计要点**：

```go
// internal/detector/resource_baseline.go
type ResourceBaseline struct {
    // key: "IP:/api/users/" 的哈希
    windows map[string]*resourceWindow
    patterns []ResourcePattern
}

type ResourcePattern struct {
    PathRegex   string `yaml:"path_regex"`   // 匹配API路径
    IDRegex     string `yaml:"id_regex"`      // 提取资源ID的正则
    WindowSec   int    `yaml:"window_sec"`    // 窗口秒数
    MaxIDs      int    `yaml:"max_ids"`       // 最大不同ID数
    Weight      int    `yaml:"weight"`        // 评分权重
}

// 示例配置：
// - path_regex: "^/api/users/[0-9]+$"
//   id_regex: "/([0-9]+)$"
//   window_sec: 60
//   max_ids: 20
//   weight: 10
```

**YAML 配置**：

```yaml
detector:
  resource_baseline:
    enabled: true
    patterns:
      - path_regex: "^/api/users/[0-9]+"
        id_regex: "/([0-9]+)"
        window_sec: 60
        max_ids: 20
        weight: 10
      - path_regex: "^/api/orders/[0-9]+"
        id_regex: "/([0-9]+)"
        window_sec: 60
        max_ids: 15
        weight: 10
```

### 2.2 P1 级增强（重要补充）

#### 2.2.1 CSRF 检测

**目标**：检测请求是否缺少 CSRF 防护

**实现方案**：

| 检测项 | 说明 |
|--------|------|
| 方法过滤 | 仅检测 POST/PUT/DELETE/PATCH 等写操作 |
| Origin 校验 | 检查 Origin 头是否与 Host 匹配 |
| Referer 校验 | 检查 Referer 是否与 Host 匹配 |
| Token 检查 | 检查请求头/请求体中是否包含 CSRF Token |
| 配置项 | 白名单路径、信任的 Origin、Token 字段名 |

```yaml
detector:
  csrf:
    enabled: true
    protected_methods:
      - POST
      - PUT
      - DELETE
      - PATCH
    token_header: X-CSRF-Token
    token_field: _csrf
    trust_origins:
      - example.com
      - api.example.com
    whitelist_paths:
      - /webhook/
      - /callback/
```

---

#### 2.2.2 撞库检测

**目标**：识别 Credential Stuffing 攻击（使用泄露凭证批量尝试登录）

**实现方案**：

| 检测项 | 说明 |
|--------|------|
| 检测维度 | 同一IP对多个不同用户名尝试失败 |
| 窗口配置 | 60s内 > 5 个不同用户名失败 |
| 与暴力破解区别 | 暴力破解：同一用户名多次失败；撞库：多个用户名各失败1-2次 |

```yaml
detector:
  credential_stuffing:
    enabled: true
    window_sec: 60
    max_unique_users: 5
    weight: 15
```

---

#### 2.2.3 API 粒度限流

**目标**：对特定 API 路径设置独立限流规则

**实现方案**：

```yaml
api_rate_limit:
  enabled: true
  default_limit: 1000  # 默认每分钟请求数
  rules:
    - path: "/api/login"
      limit: 10         # 登录接口每分钟10次
      window_sec: 60
    - path: "/api/register"
      limit: 5          # 注册接口每分钟5次
      window_sec: 60
    - path: "/api/search"
      limit: 60
      window_sec: 60
    - path: "/api/order/create"
      limit: 30
      window_sec: 60
  # 全局聚合检测（分布式攻击）
  global:
    enabled: true
    total_limit: 5000   # 所有IP总请求数/分钟
    alert_threshold: 8000 # 超过此值触发告警
```

#### 2.2.4 文件上传增强检测

**目标**：完善文件上传漏洞检测

**实现方案**：

| 检测项 | 说明 |
|--------|------|
| 扩展名黑名单 | .php, .jsp, .asp, .aspx, .phtml, .htaccess 等 |
| MIME 类型校验 | 检测伪装的文件类型 |

| 双重扩展名检测 | `file.jpg.php` 类型 |
| 文件大小限制 | 超大数据包拒绝 |
