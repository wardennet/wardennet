# 1 项目总体定位与产品边界
## 1.1 产品简介
本系统是面向中小站长、小微企业服务器集群的**集群联防IP防护系统**，采用「Go?Agent本地防护 + Python云端SaaS智能风控」双层架构。
突破单机防护局限，实现单机内核拉黑、多节点跨服务器联防、威胁情报分级流转；兼顾稳定性、低资源占用、合规隐私保护。

## 1.2 支持日志源（插件化）
### Web访问日志（默认允许上报证据）
- Nginx Access Log
- Apache Access Log
- Tomcat Access Log

### Linux系统审计日志（默认禁止上报，仅本地处理）
- Linux Auth日志（SSH登录、sudo、暴力破解行为）

### 日志策略
1. 全部日志本地解析、本地行为检测、本地ipset拦截；
2. 每种日志独立配置 `allow_upload` 开关，控制是否上报证据至云端；
3. 系统敏感审计日志默认关闭上报，落实数据最小化、隐私合规。

## 1.3 能力边界（对外免责）
? 可实现
1. Web扫描、目录爆破、漏洞探测、路径暴力探测拦截
2. 单IP高频小规模CC行为识别拦截
3. SSH暴力破解、异常登录拦截
4. **集群打散式CC识别：单节点看请求正常，跨多节点聚合判定为攻击**

? 不处理（不承诺、不宣传）
1. 网络层大流量DDoS（SYN洪水、UDP洪水等）
2. 运营商级链路带宽耗尽攻击
3. 极低频次分布式肉鸡CC（单IP请求极少，无行为特征）

## 1.4 硬性合规约束
1. MVP阶段仅白名单内测，不开放公开注册，无付费商业售卖；
2. 云端拦截海外IP接入，海外服务器仅允许Agent离线单机运行；
3. 所有攻击证据、IP威胁记录、审计日志全部配置TTL，禁止永久存储；
4. L1可疑情报默认仅本租户内部可控流转，绝不跨租户泄露；
5. 客户端上报证据云端全部二次校验，防篡改、防投毒、防刷库；
6. 敏感系统审计日志默认不上报云端。

### 第二层 Python?FastAPI 云端SaaS

- 跨节点集群CC聚合识别
- 两级白名单管理（系统全局白名单 + 租户私有白名单）
- 增量Diff版本同步引擎，按租户配置过滤下发情报，同步下发白名单变更

- 全链路操作审计日志

## 2.2 技术选型优势
### Agent选择Golang
1. 静态编译单二进制，零系统依赖，适配各类Linux发行版

3. 系统调用直接操作ipset，性能强
4. 可编译为动态插件so，实现主体开源，商业模块闭源

1. 业务逻辑迭代快，风控规则、打分、阈值便于调参
2. Web后台、接口、管理面板开发效率高
3. 便于对接数据库、缓存、对象存储

# 3 Agent客户端详细设计（Golang）
## 3.1 核心设计原则
1. **无本地Web管理界面，不监听外网TCP端口**；全部管理走CLI + UnixSocket；
2. 优先保障业务服务器稳定性，异常自动降级，不影响业务；
3. 日志断点续读，日志轮转兼容，不丢日志、不重复处理；
4. 支持完全离线单机运行，不依赖云端。

## 3.2 日志插件框架
内置解析器：`nginx_access` / `apache_access` / `tomcat_access` / `linux_auth`

统一事件结构体
```go
type Event struct {
    SrcIp        string
    Timestamp    int64
    EventType    string
    Uri          string
    StatusCode   int
    WindowCount  int
    LocalRiskScore float64
}
```

每类日志独立配置 `allow_upload: bool`，控制证据是否上报云端。

## 3.3 本地防护能力
1. tail日志持续消费，断点记录偏移，日志轮转自动处理；
2. 可配置滑动统计窗口：10s / 30s / 60s；
3. ipset集合管理黑名单，增量add/del，避免频繁全量reload；
4. 本地维护独立ipset白名单集合；本地行为检测命中白名单IP直接跳过拉黑逻辑；
5. 本地TTL自动解封；
6. 本地黑白名单配置，**优先级高于云端下发黑白名单**。

## 3.4 CLI管理（UnixSocket通信）
```bash
# 查看封禁列表
./agent blocklist show
# 手动解封IP
./agent blocklist del [IP]
# 手动拉黑IP，指定TTL秒
./agent blocklist add [IP] --ttl [秒]
# 查看本地白名单
./agent whitelist show
# 添加本地白名单IP
./agent whitelist add [IP]
# 删除本地白名单IP
./agent whitelist del [IP]
# 查看拦截统计
./agent stats
# 重载配置文件
./agent reload
# 查看运行状态
./agent status
```

## 3.5 Agent TTL配置（yaml）
```yaml
agent:
  local_block_ttl: 3600
  cloud_block_ttl: 7200
```
约束：`cloud_block_ttl` 不能超过云端下发的等级最大TTL，超出部分被云端上限截断。
断网状态下完全使用本地配置运行。

## 3.6 插件加载机制
1. Agent开源主体启动时检测本地商业插件 `libcloudplugin.so`；
2. **无插件：离线单机模式，仅本地防护，无云端联防、情报同步、云端白名单同步**；
3. **存在合法so插件：开启完整商业能力：鉴权、证据上报、Diff同步（含黑白名单变更）、远程指令接收**。

## 3.7 Agent禁止功能清单
? 不开放Web管理页面
? 不监听任何外网TCP端口
? 不永久保存日志与拦截记录
? 不无条件上报敏感审计日志

## 4.2 核心风控业务规则
### 4.2.1 租户一票制防刷机制
同一租户下多Agent上报同一个IP，云端**只计一次有效投票**；防止攻击者篡改Agent大量上报恶意证据污染情报库。

### 4.2.2 新租户冷却期
新租户72小时内上报证据权重降低，不直接升级L3高危情报，抵御批量注册女巫攻击。

### 4.2.3 三级威胁分级（含租户内部L1共享可配置）
- **L1 可疑：证据可信度不足**
  默认仅云端留存观察，**默认不下发任何Agent（含本租户Agent），不执行主机拉黑**，仅累积分数等待交叉验证。
  > 租户可主动开启「租户内部L1共享」开关：**仅将本租户自身产出的L1下发给本租户全部Agent；其他租户的L1永远不会下发**。开启后误封风险上升，业务风险由租户自行承担；L1数据永远不会跨租户泄露。
- **L2 中度威胁：多租户交叉验证通过，可信度中等**
  有限分发，通过Diff增量同步下发至租户Agent执行拦截。
- **L3 高危威胁：多租户充分交叉验证，可信度高**
  全局可信情报，下发租户Agent执行拦截。

### 4.2.4 集群打散CC识别
聚合同一租户全部Agent上报行为，识别单节点看正常、多节点聚合后为攻击的打散CC；判定结果仅对本租户生效，不跨租户扩散。

### 4.2.5 IP白名单两级体系
分为**系统全局白名单**、**租户私有白名单**两级。
1. **系统全局白名单（平台管理员维护）**
- 作用范围：全部租户；
- 命中IP：不参与威胁打分、不会生成任何等级(L1/L2/L3)威胁记录，不会下发至任何Agent黑名单；
- 若IP已经存在威胁记录，直接标记豁免，同步下发remove指令清除所有Agent上该IP黑名单。

2. **租户私有白名单（租户后台自行维护）**
- 作用范围：仅当前租户下全部Agent节点；对其他租户完全无效；
- 命中IP：在本租户内跳过威胁升级、不会下发到本租户Agent黑名单；其他租户仍然可以正常标记、拉黑该IP。

#### 完整优先级
`系统全局白名单 > 租户私有白名单 > Agent本地配置白名单 > L3 > L2 > L1 > 云端下发黑名单 > Agent本地配置黑名单 > Agent CLI手动拉黑`

> 业务行为：白名单IP仍然正常采集日志、上报事件，后台可以查看行为记录，**仅跳过封禁动作**。
> 增加TTL支持：全局白名单、租户私有白名单均支持设置过期时间，到期自动失效，同步下发白名单删除变更；也支持永久生效。
> 白名单仅做豁免封禁，**不会删除历史攻击事件与威胁记录，保留用于审计**；IP移出白名单后恢复原有威胁等级逻辑。

## 4.3 租户可配置参数（yaml）
```yaml
tenant_config:
  enable_internal_l1_share: false   # 是否开启租户内部L1共享，默认关闭
  pull_threat_level: "L2_L3"        # 可选值 L2_ONLY / L2_L3 / ALL
                                    # ALL 需要 enable_internal_l1_share=true 才生效
```

> Web后台风险提示文案：
> ??开启【租户内部L1数据共享】：本租户各个服务器上报的可疑L1威胁，将同步到该租户下所有节点执行拦截。该模式会增强拦截效果，但**误封风险明显升高，请评估业务风险后开启**；L1数据永远不会泄露给其他租户。

## 4.4 IP等级完整流转逻辑
1. Agent上报攻击事件 → 云端标记L1，默认仅云端存储，不下发Agent；
2. 租户开关关闭：L1仅做观察，分数达标才升级L2/L3后下发；
3. 租户开启`enable_internal_l1_share`且`pull_threat_level=ALL`：本租户产出L1进入租户Diff变更集下发本租户全部Agent；外部租户L1全部丢弃；
4. 多租户交叉上报，分数达到阈值升级L2/L3，进入同步池下发Agent拉黑；
5. 时间流逝分数衰减，等级回落L1：
   - 开关开启：继续按配置决定是否下发；
   - 开关关闭：生成remove变更，Agent解除拉黑，回到云端仅观察状态；
6. **租户关闭L1共享开关瞬间：云端批量生成remove变更，清除所有已下发L1黑名单，仅保留L2/L3**；
7. IP命中系统全局/租户私有白名单：豁免封禁，生成remove清理Agent黑名单；IP移出白名单后恢复原有威胁等级分发逻辑。

## 4.5 分层存储设计
1. PostgreSQL主库：存储精简特征，IP、租户ID、agent_id、威胁等级、分数、时间、工单审计记录；**不存储完整原始日志**。
2. 对象存储/本地文件：存储原始攻击证据片段，UUID索引引用；
3. Redis：窗口统计、限流、版本号缓存、白名单变更缓存；
4. TTL自动清理：
   - 原始证据文件：默认保留7天；申诉工单关联证据自动延期；
   - 事件特征记录：默认保留14天；
   - IP威胁记录：按L1/L2/L3分级TTL自动衰减过期；
   - 白名单记录：按配置的过期时间自动失效。

## 4.6 上报限流&采样策略
1. Agent本地做事件聚合，合并高频重复攻击事件，减少上报量；
2. 云端按Agent做QPS限流，超限丢弃冗余上报，保护云端；
3. 高负载下支持租户开启采样上报，进一步降低压力。
> 注意：上报丢弃不会影响Agent本地拦截，只影响云端情报积累。

## 4.7 增量Diff版本同步机制
### 解决问题
避免全量黑名单拉取带来带宽爆炸、CPU压力大；只下发变更；同时支持黑白名单双变更同步。

Diff数据包示例
```json
{
    "server_version": 12086,
    "full_sync": false,
    "add_list": [{"ip":"x.x.x.x","level":"L3","ttl":7200}],
    "remove_list": ["y.y.y.y"],
    "whitelist_add": ["192.168.1.100","10.0.0.5"],
    "whitelist_remove": ["203.0.113.10"]
}
```
- `add_list`：新增黑名单IP
- `remove_list`：移除黑名单IP
- `whitelist_add`：新增租户生效白名单IP
- `whitelist_remove`：移除租户生效白名单IP

触发全量同步场景：Agent首次启动、本地快照损坏、版本差距过大。全量同步下发完整黑名单快照 + 当前租户生效完整白名单快照。

### 分发过滤规则（完整，含白名单）
1. 读取租户配置：`enable_internal_l1_share`、`pull_threat_level`；读取系统全局白名单、该租户私有白名单。
2. 若IP命中**系统全局白名单**：直接过滤，不加入add_list；如Agent已存在该IP黑名单，则加入remove_list。
3. 若IP命中**当前租户私有白名单**：对本租户过滤，不加入add_list；如Agent已存在该IP黑名单，则加入remove_list。
4. **其他租户产生的L1，无论任何配置，一律过滤，绝不下发**。
5. L1共享开关关闭（默认）：全部L1过滤，仅L2、L3参与同步分发。
6. 开关开启且`pull_threat_level=ALL`：**仅本租户自身产出的L1**加入本租户增量变更集下发；外部租户L1全部丢弃。
7. 租户关闭L1共享瞬间，批量输出remove列表，清除Agent上全部L1黑名单。

### 轮询策略
- 无变更：60?120s轮询；
- 收到变更：缩短轮询间隔快速追齐版本，之后恢复长间隔。

## 4.8 申诉复核流程
1. 用户Web端提交IP误封申诉；
2. 后台查看证据、威胁等级、分数来源；
3. 人工复核可选操作：撤销IP威胁标记 / 将IP加入租户私有白名单；下发remove指令给Agent，调整威胁分数；
4. 全流程留审计日志。

## 4.9 Web后台白名单管理能力
1. 管理员后台：系统全局白名单管理，IP增删、备注、设置有效期TTL；
2. 租户后台：租户私有白名单管理，IP增删、备注、可选配置过期时间；
3. 白名单变更产生变更事件，纳入Diff同步下发至租户全部Agent。

---

# 5 完整数据流闭环
1. Agent读取日志，解析攻击事件，本地滑动窗口判定；命中本地白名单直接跳过拦截；否则执行ipset本地拦截；
2. 允许上报的事件经过本地聚合后上报云端；
3. 云端接收证据，校验合法性，执行租户一票制防刷；
4. 云端更新IP威胁分数，执行等级流转（L1→L2→L3，衰减回落）；
5. 结合系统全局白名单、租户私有白名单、租户情报配置，过滤情报，生成租户专属Diff增量变更集（含黑名单、白名单变更）；
6. Agent轮询拉取Diff包，更新本地ipset黑名单与白名单集合，执行add/remove；
7. 双端TTL自动过期清理；白名单到期自动失效同步变更；
8. 用户可提交申诉，人工复核撤销黑名单或加入白名单。

---

# 6 故障降级边界
1. 云端宕机/网络断开：Agent自动进入离线模式，仅使用本地黑白名单、本地规则、本地TTL独立防护，业务不受影响；云端下发的黑白名单变更不再更新；
2. Agent恢复联网：拉取Diff补全黑名单快照与白名单快照；
3. Agent本地快照损坏：触发一次全量同步重建黑名单+白名单；
4. 证据上报被限流丢弃：不影响Agent本地拦截，仅云端情报积累受影响。

# 7 非功能需求
## 7.1 Agent性能

- 低内存占用，长期运行无内存泄漏

- 存储自动TTL清理，数据库不会无限膨胀
- 接口限流防护，抗大量上报冲击

## 7.3 安全合规
- Agent无外网监听端口；
- 云端证据全量校验，防投毒；
- 数据TTL自动销毁；
- L1严格租户隔离，可配置开关；
- 两级白名单操作全链路审计日志留存。

# 10 产品核心壁垒
1. **工程壁垒**：增量Diff大规模同步、黑白名单一体化同步、分层存储防膨胀、双端TTL解耦、可开关租户内L1共享机制；抄代码容易，边界case很难完整复刻。
2. **风控壁垒**：租户一票制防刷、L1租户隔离、分数衰减流转、两级白名单隔离、集群打散CC识别；是整套规则体系，不是单一算法。
3. **合规壁垒**：全链路TTL销毁、数据最小化、敏感日志隔离、风险提示闭环。
4. **开源商业模式壁垒**：主体开源引流，核心联防能力由闭源so插件+云端私有逻辑实现；对手拿到开源代码只能做单机防护，完整集群联防需要从零重写整套云端系统。
5. **运营壁垒**：真实攻击样本、误封案例积累、持续调参迭代，属于时间沉淀护城河。
