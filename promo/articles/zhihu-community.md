# 中小站长如何低成本防护 Web 攻击？商业 WAF 太贵，开源脚本又不够用

作为一个同时运营着 5 个小站的"副业站长"，这个问题我琢磨了快一年。

先给你算笔账。假设你手里有 3 台轻量应用服务器，分别跑了一个 WordPress 博客、一个小型 SaaS API、一个 Typecho 论坛。服务器配置都是 2C4G，每月租金加起来大约 300 块。现在的问题是：**怎么在不增加太多成本的前提下，把安全这件事做了？**

## 先盘点一下行业现状

目前市面上的 Web 攻击防护方案，大致分三档：

### 第一档：商业 WAF（Web Application Firewall）

**代表产品**：阿里云 WAF、腾讯云 WAF、XX盾、Cloudflare Enterprise、Akamai Kona Site Defender。

**价格区间**：

| 厂商 | 入门版价格 | 适合场景 |
|------|----------|---------|
| 国内某云厂商 WAF | **2000-5000 元/月** | 单域名或少量域名 |
| 国外某知名盾 | **500-2000 美元/月** | 企业级 CDN + 防护 |
| 开源企业版 WAF（付费支持） | **1000-3000 元/月** | 自建机房 + 商业支持 |

**痛点分析**：

1. **太贵**。对于我这种副业站长，一个月 WAF 的费用比服务器本身还贵——这显然不合理。一个月赚 2000 块的小站，花 2000 块买 WAF？不如直接关站。
2. **太重**。商业 WAF 通常需要你把 DNS 解析切到它们那边（CNAME 接入），或者在服务器前加一层反向代理。对于技术能力一般的中小站长，这个操作本身就有门槛。
3. **功能冗余**。你一个小博客，用不上"机器学习自动攻击识别"、"Bot Management"、"API 保护"这些高级功能。但你又不能只买子功能。

但必须承认，**商业 WAF 的效果确实好**。大厂有能力花大价钱搞实时威胁情报、规则更新、CDN 边缘节点清洗。如果你月活 10 万+、有专门的运维团队，商业 WAF 是正确选择。

### 第二档：开源脚本和工具

**代表产品**：fail2ban、Wordfence（WordPress 插件）、Nginx ModSecurity（OWASP Core Rule Set）、各种 GitHub 上的小脚本。

**价格**：免费。

**痛点分析**：

1. **误报率高**。fail2ban 用正则匹配 access log，规则是静态的。你加一条 404 扫描的规则，结果搜索引擎爬虫、正常的 favicon 请求、CDN 的健康检查一起被封。
2. **规则维护成本高**。OWASP Core Rule Set 确实全，但你得从中挑出适合自己业务的规则、关掉会误杀的规则、自定义业务特有的路径。一个小时能配好的，大概率会在生产中出问题。
3. **单机阈值能被绕过**。Grep + ipset 的组合，攻击者只要把 QPS 压到阈值以下就没事了。
4. **很多脚本只针对 WordPress**。Wordfence 是好东西，但你 API 服务器、Typecho 论坛怎么防护？每个服务装一套？维护不过来。

开源工具够用吗？**够用。但不够精准，不够省心。** 就像一把锤子能钉钉子，但你得自己调整角度、控制力度，还得盯着别砸到手。

### 第三档：轻量 SaaS / 半托管服务

**价格区间**：50-500 元/月。

这个档位的产品通常是云厂商提供的"云防火墙"轻量版，或者专门做 Bot Management 的创业公司。**但说实话，这个档位的选择非常少，而且很多是阉割版，功能上跟免费的差别不大**。

## 成本对比：真实数字说话

让我把三种方案的年度成本列出来，一目了然：

| 方案 | 3 台服务器年费 | 维护时间/月 | 防护效果 |
|------|:------------:|:----------:|:-------:|
| 裸奔（什么都不做） | **0 元** | **0 分钟** | ❌ 被扫、被爆破、被动挨打 |
| fail2ban + 手工脚本 | **0 元** | **60-120 分钟** | ⚠️ 能挡明显扫描，慢速/分布式绕过 |
| **WardenNet Agent（开源）** | **0 元** | **15-30 分钟** | ✅ 基线自学习 + 5 维评分，单机误报低 |
| WardenNet 协同网络（SaaS 增值） | **1200 元（约 100/月）** | **15 分钟** | ✅ 单机 + 全网协同，分布式攻击也识别 |
| 商业 WAF（入门） | **24000-60000 元** | **30-60 分钟** | ✅✅ 效果最好，但最贵 |

等等，WardenNet Agent 免费？

**对，完全免费开源**。

我一开始也不敢信——一个带基线自学习、5 维一致性评分、8 层防误报的防护工具，免费开源？去看了 GitHub 仓库才确认，**Agent 部分是 AGPLv3 许可，任何人可以免费使用、修改、分发**。

它的商业模式很清晰：**单机 Agent 免费开源，云端协同网络是商业增值服务**。这跟 GitLab（社区版免费、企业版收费）、Kafka（开源、托管版收费）一个路子。

## 为什么 WardenNet Agent 对中小站长特别友好？

我用了几周的时间把它在我的 3 台服务器上跑起来，总结了它对中小站长特别友好的几个原因：

### 1. 安装真的只需要 5 分钟

```bash
# 下载
wget https://github.com/wardennet/agent/releases/download/v0.4.0/wardennet-linux-amd64

# 配置（只改 2 处）
sudo wardennet init-config /etc/wardennet/config.yaml

# 启动
sudo systemctl enable --now wardennet
```

就这三步。不需要 Docker、不需要依赖、不需要编译。

### 2. 资源占用极低

| 指标 | 数值 | 对比参考 |
|------|:----:|---------|
| 二进制体积 | **极轻量** | 一张中等大小的 PNG 图片 |
| 运行内存 | **10-30MB** | 跟一个浏览器标签页差不多 |
| CPU 占用 | **<1%**（空闲） | 基本可以忽略 |

我那台最老的 1C2G 服务器，跑 WordPress + MariaDB + WardenNet 之后，系统负载才 0.3。完全没感觉。

### 3. 不需要懂网络安全

你不需要知道什么是"基线自学习"、"5 维一致性评分"、"滑动窗口"。你只需要做两件事：

- 告诉它你的 Nginx access log 在哪
- 把你的内网 IP 加进白名单（可选但推荐）

其余的——敏感路径关键词、攻击模式匹配、防误报机制——**全部用程序内置的默认值**。这些默认值是开发者经过大量实测调优的。

### 4. 误报率真的低

我用了一个月，**没有出现过一次封错人**的情况。

我之前用 fail2ban 的时候，至少手动解封过 3 次——一次是搜索引擎爬虫的高并发，一次是我自己在服务器上跑性能测试，一次是某个运维同事的健康检查脚本。WardenNet 一次都没有。

为什么？因为它不是简单看 QPS 阈值，而是**先学习你的服务器正常时长什么样，再看现在长什么样偏离了多少**。基线自学习 + 5 维一致性评分的组合，比静态阈值聪明太多了。

### 5. 断网也能工作

这点对中小站长很重要。你的服务器在国内某个不太靠谱的云厂商上跑，万一云端服务偶尔抽风（国内 SaaS 的常态），Agent 不会跟着挂掉。它自动退化为纯本地模式，该检测检测，该封禁封禁。

## 要不要升级到协同网络？

这取决于你的具体情况。先跑一段时间单机 Agent，如果出现了以下任一情况，再考虑升级：

| 场景 | 单机能不能扛 | 协同能带来什么 |
|------|:----------:|:-------------:|
| 单 IP 扫描（QPS 偏高） | ✅ 能 | 没什么区别 |
| 慢 QPS 扫描（QPS 压得低） | ⚠️ 勉强能（依赖基线偏离） | ✅ 全网威胁情报加分，更容易识别 |
| **分布式/代理池扫描** | ❌ 扛不住 | ✅ 云端聚合全网信号，IP 聚类识别 |
| 打散型 CC | ❌ 扛不住 | ✅ 全网目标路径聚合 |
| 威胁情报实时更新 | ❌ 没有 | ✅ 新的 bot UA、新的敏感路径 |

如果你只有 1-3 台服务器，流量不大，**单机 Agent 完全够用**。我就是这个场景，所以暂时没升级。

如果你有 10+ 台服务器、或者多个域名、或者业务已经有一定流量，**协同网络的性价比就很高了**——按 100 元/月算，一年也才 1200 元，比商业 WAF 便宜一个数量级。

## 合规边界声明

在做安全防护这件事上，有几个合规问题需要明确，这也是 WardenNet 在设计时特别注意的：

1. **本地 Agent 不收集任何用户数据**。它只处理服务器上已有的 access log，不抓取、不上传、不存储用户访问内容。
2. **云端协同上传的是"威胁事件元数据"，不是完整日志**。比如"IP 1.2.3.4 在服务器 A 上 60 秒内请求了 80 次敏感路径"，而不是"IP 1.2.3.4 访问了 /api/xxx 返回了 200"。
3. **用户数据不上传**。请求体、Cookie、URL 参数等业务敏感信息，默认不被上传云端。
4. **Linux Auth Log 默认不上报**。SSH/登录审计日志（`/var/log/auth.log`）包含大量系统内部信息，默认 `allow_upload: false`，只有在审计场景才需要显式开启。
5. **最终决策权永远在本地**。Cloud SaaS 只下发评分，不下发封禁指令。即使云端被攻击，Agent 也不会被远程控制误封真实用户。

如果你业务在中国大陆，遵循《网络安全法》和《数据安全法》，以上边界完全合规。如果业务涉及特殊行业（金融、医疗），建议额外做一次合规评估。

## 给中小站长的行动清单

如果你也想低成本解决 Web 防护问题，我建议按以下顺序来：

**第一步（本周就能做）**：给所有服务器安装 WardenNet Agent，`mode: report` 跑 48 小时观察评分分布。

**第二步**：把 `mode` 切换到 `block`，配置好内网白名单。之后每月检查一次 ipset 里有没有误封（概率很低）。

**第三步（可选）**：如果发现有分布式扫描、或者有 10+ 台服务器了，再考虑接入协同网络。

**第四步**：别做 DDoS 防护。WardenNet 不承诺防 SYN/UDP 洪水。如果你真的遇到了这种级别的攻击，说明你的业务已经上了一个台阶，这时候商业 WAF 也负担得起了。

## 最后

中小站长在安全这件事上的困境，本质上是**"没有一个对他们友好的选项"**。商业 WAF 贵，开源脚本弱，自建太累。

WardenNet Agent 试图填补这个空白——**免费、轻量、聪明、单机可用、协同更强**。它不是完美的，但对大多数中小站长来说，它可能是目前最合适的选择。
