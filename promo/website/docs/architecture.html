系统架构总览

数据流架构

一次攻击请求从产生到被拦截的完整流程：

Agent 核心模块

Agent 采用模块化设计，各模块通过接口解耦，便于单元测试和独立演进。

模块路径职责
logparser internal/logparser/ 实时 tail 多个日志文件（Nginx/Apache/Tomcat/Linux Auth），解析为统一 Event 结构。支持 inode 变化检测日志轮转，断点续读不丢事件。
detector internal/detector/ 基线自学习检测引擎核心。三档滑动窗口（10s/30s/60s）并行统计，8 维相对特征基于 P95 偏差评分，3 维绝对特征固定权重。内置 Preload 全量扫描 + MAD 极端值剔除。
cloudsync internal/cloudsync/ 云端同步调度引擎。四条后台协程：heartbeatLoop（心跳）、diffLoop（规则增量同步）、commandLoop（远程命令）、featureLoop（威胁情报拉取）。智能同步：global base + tenant diff。
ipsetutil internal/ipsetutil/ ipset/iptables 黑白名单管理。自动创建 wardennet_blacklist（hash:ip）和 wardennet_whitelist（hash:net），注入 DROP 规则。
plugin internal/plugin/ CloudPlugin Go plugin 加载器。通过 stlplugin.Open + Lookup('NewPlugin') 加载 .so，无插件时降级为 NoopPlugin（零开销）。
ttl internal/ttl/ 封禁 TTL 过期管理器。后台协程每 30s 清理过期条目，支持本地/云端两种 TTL 源。
snapshot internal/snapshot/ 状态快照持久化。每 60s 自动保存黑名单 + TTL 到 state.json，启动时自动恢复。
unixsocket internal/unixsocket/ 本地命令通信服务端。Unix Socket（/var/run/wardennet.sock），0600 权限，支持 JSON 协议的 CLI 命令。
config internal/config/ YAML 配置加载 + 热重载。每 5s 轮询配置文件变化，变更实时生效（除 log_sources 需重启）。

检测引擎

基线自学习引擎（v0.8+）是 WardenNet 的核心。评分过程分为三步：

第一步：基线自学习（离线 Preload + 在线更新）

算法
// Preload 全量扫描（启动时执行一次）
function preload(access_log):
  全量读取日志 → 按 5min 时间桶分组
  ↓
  MAD 方法剔除扫描器/爬虫极端桶
  ↓
  用干净数据算 P50 / P95 / P99
  ↓
  应用 MIN_BASELINE_QPS 硬保底 (≥ 1.0 req/s)
  ↓
  设置三档基线 + confidence

// 在线更新（每 10s 执行）
function baselineUpdateLoop():
  遍历所有活跃 IP → 聚合全局 counters
  ↓
  [v0.9 G1 预筛] 基线自学习抗干扰 → 硬阈值跳过扫描器 IP
  ↓
  [v0.9 G2 双重管线] removeOutliersMAD(k=5) → trimExtremes(factor=10)
  ↓
  计算分位数 → 硬保底 → 指数衰减融合
  ↓
  三档基线 P95 滚动更新

第二步：评分公式

Scorer.ScoreWithDetail()
// 相对特征评分（8 维基线偏差）
for each relative dimension d:
  p95, conf = baselines[w].GetWithConfidence(d)
  value    = counters[d] / windowSec
  dev      = value / p95  (cap MAX_DEVIATION=1000)
  pts      = deviationToScore(dev, sensitivity)

// 单维度封顶（核心防误杀）
活跃维度数 == 1 → 相对总分 cap 到 score_medium(30)   // 单维度永远不封
活跃维度数 ≥ 2 → 每个维度 pts cap 到 score_high × 60%(30)

// 绝对特征评分（3 维固定权重，不受封顶限制）
DangerousPattern = min(cnt × weight, singleEventCap=25)
DangerousMethod  = min(cnt × weight, singleEventCap=25)
FileUpload       = min(cnt × weight, singleEventCap=25)

// 置信度打折
baselineConf < 0.3 → 相对总分 ×= 0.5
baselineConf < 0.1 → score_high 强制降到 49 (永不封禁)

// 最终分
总分 = min(相对分 + 绝对分 - 防误杀降权, score_high)
取 max(三档窗口)

第三步：Consistency 行为连贯性评分

Scorer 给了 score_high 后，还需要通过 Consistency 5 维 gate：

维度真人/合法客户端扫描器阈值
前缀连贯连续请求同前缀，avgRunLen ≥ 3每条路径切换前缀≥ 3 或 dominant ≥ 50%
新颖度饱和前 30% 覆盖 70%+ 路径一路扫一路新前 30% ≥ 70% 且后 30% ≤ 40%
路径集中Top5 路径覆盖 ≥ 25%每条路径 1-2 次≥ 25%
状态同质同路径返回稳定状态码发散路径各撞一次 404CV < 0.6
方法语义GET/POST 为主混合方法或全 GET 探测GET [50%,99%]

ConsistencyScore ≥ 4 → 判定为 BENIGN（合法）→ 强制降权到 score_medium（30），让多事件确认机制处理。

防护分层

L1

流量异常检测

QPS 突增、404 扫描——相对特征基线偏离

L2

攻击特征识别

Bot UA、敏感路径、危险 HTTP 方法、攻击 Payload

L3

协同信号

多维度关联分析（Consistency 5 维行为连贯）

L4

防误杀机制

空 Referer 封顶、401 降权、legitimateUserContext、单维度封顶

L5

基线自学习抗干扰

智能预筛硬阈值 + MAD + trimExtremes 双重管线

L6

快速响应

白名单绝对豁免、ForceBlock 覆盖、TTL 自动解封
