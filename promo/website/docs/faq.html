常见问题

以下是 WardenNet 社区中最常被问到的问题。如果你没有在这里找到答案，可以提交 Issue 或联系我们。

架构与关系

WardenNet 采用 Agent + Cloud SaaS 的混合架构：

  • Agent（开源）：部署在每台受保护的服务器上，本地运行基线自学习检测引擎，负责实时日志解析、威胁评分和 ipset/iptables 封禁。单机可独立运行。
  • Cloud SaaS（闭源）：多租户管控平台，提供威胁情报共享、远程命令调度、审计合规等协同能力。Agent 通过 CloudPlugin（.so 动态库）与云端对接。

Agent 是防护的核心，Cloud 是增强能力。没有 Cloud，Agent 依然能完整工作。

完全不需要。Agent 设计上就是可以脱离云端独立运行的。

只需在配置中设置 cloud.enabled: false（默认就是 false），Agent 就会以纯本地模式运行：

  • ✅ 实时日志解析和威胁评分正常工作
  • ✅ 自动 ipset/iptables 封禁正常工作
  • ✅ 本地白名单完全生效
  • ❌ 不发起任何出站 HTTP/HTTPS 请求
  • ❌ 不使用云端威胁情报（仅用内置特征库）

适合离线环境、内网隔离服务器或首次部署阶段。

配置相关

在 YAML 配置文件的 ipset.whitelist 段添加即可：

YAML
ipset:
  whitelist:
    - 127.0.0.1                    # 本机回环
    - ::1                                 # IPv6 回环
    - 192.168.1.0/24                  # CIDR 网段
    - 203.0.113.50                # 单个 IP
    - 2001:db8::/32                 # IPv6 网段

白名单特性：

  • 优先级最高：命中白名单的 IP 跳过所有检测，永不封禁
  • 支持精确 IP、CIDR 网段、IPv6 地址
  • 底层 ipset 类型为 hash:net（自动重建）
  • 修改后 5 秒内自动热重载

Agent 自动创建两个 ipset 集合：

集合名称类型用途
wardennet_blacklisthash:ip黑名单，检测到的恶意 IP 会被加入此集合
wardennet_whitelisthash:net白名单，支持 CIDR 网段和 IPv6 地址

验证命令：

Shell
ipset list wardennet_blacklist
ipset list wardennet_whitelist
iptables -S INPUT | grep wardennet

封禁时长由 agent.local_block_ttl 配置决定，默认 3600 秒（1 小时）。

TTL 到期后 IP 自动从 ipset 黑名单中移除，iptables DROP 规则不再拦截。

常用 TTL 设置：

  • 3600 = 1 小时（默认）
  • 7200 = 2 小时
  • 86400 = 1 天
  • 259200 = 72 小时（3 天）

TTL 信息保存在 Agent 快照文件中，重启后自动恢复倒计时。

运维操作

推荐使用 CLI 方式（同时清理 TTL 计时器）：

Shell
# 方式一：wardennet CLI（推荐）
wardennet blocklist del 203.0.113.100

# 方式二：socat + JSON 协议
echo '{"command":"blocklist.del","args":{"ip":"203.0.113.100"}}' | socat - UNIX-CONNECT:/var/run/wardennet.sock

# 方式三：直接操作 ipset（不推荐，TTL 管理器不同步）
ipset del wardennet_blacklist 203.0.113.100

如果你需要清空整个黑名单集合：

Shell
# 紧急停封所有 IP（秒级生效）
ipset flush wardennet_blacklist

# 如需永久清空，还需删除快照文件防止重启恢复
rm -f /etc/wardennet/state.json
