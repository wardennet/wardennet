故障排查

本手册覆盖生产环境中最常见的故障场景，提供系统化的排查步骤和解决方案。遇到问题先在日志中定位，再按流程检查。

日志位置与查看

日志文件路径

Shell
# 主日志文件（默认路径）
/var/log/wardennet/agent.log

# 查看日志文件
tail -f /var/log/wardennet/agent.log

# 只看 warn/error 级别
grep -E "level=(warn|error)" /var/log/wardennet/agent.log

# 最近 1 小时的拉黑事件
grep "auto blocked" /var/log/wardennet/agent.log | tail -20

systemd journalctl

Shell
# 实时跟踪日志
journalctl -u wardenet -f

# 今天以来的日志
journalctl -u wardenet --since "today"

# 最近 30 分钟
journalctl -u wardenet --since "30 minutes ago"

# 只看错误级别
journalctl -u wardenet -p err..alert

# 最近 50 行
journalctl -u wardenet -n 50 --no-pager

systemd 状态检查

Shell
# 查看服务状态
systemctl status wardenet
# 预期：active (running)

# 只检查活跃状态（退出码 0 = 正常）
systemctl is-active wardenet

# 是否开机自启
systemctl is-enabled wardenet

# 查看失败的服务
systemctl --failed | grep wardennet

# 重启服务
systemctl restart wardenet

ipset 命令验证

Shell
# 列出所有 ipset 集合
ipset list | grep wardennet

# 查看黑名单详情 + 条目
ipset list wardennet_blacklist

# 测试某个 IP 是否在黑名单中
ipset test wardennet_blacklist 203.0.113.100

# 测试某个 IP 是否在白名单中
ipset test wardennet_whitelist 127.0.0.1

# 添加 / 删除 / 清空
ipset add    wardennet_blacklist 203.0.113.100
ipset del    wardennet_blacklist 203.0.113.100
ipset flush  wardennet_blacklist
ipset destroy wardennet_blacklist   # 销毁整个集合

iptables 规则检查

Shell
# 查看 INPUT 链中的 wardennet 规则
iptables -S INPUT | grep wardennet
# 预期：-A INPUT -p tcp -m set --match-set wardennet_blacklist src -j DROP

# 查看规则详情 + 包计数
iptables -L INPUT -n -v --line-numbers | grep -A 3 wardennet

# 手动添加规则（Agent 启动时会自动执行）
iptables -I INPUT -p tcp -m set --match-set wardennet_blacklist src -j DROP

# 手动删除规则
iptables -D INPUT -p tcp -m set --match-set wardennet_blacklist src -j DROP

# 自动清理所有 wardennet 规则
iptables -S INPUT | grep wardennet | sed 's/-A/-D/' | while read cmd; do iptables $cmd; done

常见错误与解决方案

Q1：Agent 启动后立即退出

排查步骤命令期望
1. 查看详细错误journalctl -u wardenet -n 50 --no-pager找到 ERROR 或 FATAL 日志
2. 手动前台运行/opt/wardennet/wardennet --config /etc/wardennet/config.yaml直接看到报错
3. 检查 ipsetwhich ipset && ipset --versionipset ≥ 6.x
4. 检查 iptableswhich iptables存在且可执行
5. 检查配置 YAML 语法python3 -c "import yaml; yaml.safe_load(open('/etc/wardennet/config.yaml'))"无报错输出
6. 检查日志目录权限ls -la /var/log/wardennet/root 可写

Q2：IP 未被真正封禁

排查链路（日志 → ipset → iptables）
# Step 1: 日志中是否有拉黑记录
grep "auto blocked" /var/log/wardennet/agent.log | grep "203.0.113.100"
if [ $? -ne 0 ]; then
  # 没有拉黑记录 → 看是否在白名单
  ipset test wardennet_whitelist 203.0.113.100
fi

# Step 2: ipset 中是否存在
ipset test wardennet_blacklist 203.0.113.100
# 期望：203.0.113.100 is in set wardennet_blacklist.

# Step 3: iptables DROP 规则是否存在
iptables -S INPUT | grep wardennet
# 应有 --match-set wardennet_blacklist src -j DROP

# Step 4: 检查 TTL 是否在倒计时
ipset list wardennet_blacklist | grep "203.0.113.100"

Q3：ipset 操作报 "set doesn't exist"

Shell
# Agent 启动时应自动创建，被误删时手动重建
ipset create wardennet_blacklist hash:ip
ipset create wardennet_whitelist hash:net family inet hashsize 1024 maxelem 65536

# 重启 Agent 补齐 iptables 规则
systemctl restart wardenet

Q4：检测引擎过于敏感（频繁误杀）

Shell（排查）
# Step 1: 开启 debug 看评分详情
sed -i 's/level: info/level: debug/' /etc/wardennet/config.yaml

# Step 2: 定位误杀 IP
grep "auto blocked" /var/log/wardennet/agent.log | head -5

# Step 3: 看该 IP 的评分详情
grep "detector score detail" /var/log/wardennet/agent.log | grep "ip=<误杀IP>"

# Step 4: 恢复日志级别
sed -i 's/level: debug/level: info/' /etc/wardennet/config.yaml

调整方案（按推荐顺序尝试）：

  • 调低灵敏度：sensitivity: low（偏离 10x 才触发）
  • 提高封禁阈值：score_high: 60 或更高
  • 确认 legitimateUserContext 降权是否触发
  • 观察基线学习日志，确认基线正在追踪正常流量

Q5：Unix Socket 无法连接

Shell
# 检查 socket 文件是否存在
ls -la /var/run/wardennet.sock
# 预期：srwx------

# 检查权限（root 可访问）
stat /var/run/wardennet.sock

# 检查 Agent 是否在运行
systemctl status wardenet

# 重启后再试
systemctl restart wardenet

Q6：CloudPlugin 加载失败

Shell
# 查看插件加载日志
journalctl -u wardenet | grep -i plugin

# 常见场景
# plugin file not found — 检查 cloud.plugin_path 配置
# plugin open failed: permission denied — .so 文件权限应为 644
# cloudsync auth failed — tenant_id 或 agent_secret 错误

# 验证 .so 文件
file /usr/lib/wardennet/libcloudplugin.so
ls -la /usr/lib/wardennet/libcloudplugin.so

# 临时降级（跳过插件）
sed -i 's/enabled: true/enabled: false/' /etc/wardennet/config.yaml

紧急操作手册

Shell
# 紧急停封所有 IP（秒级生效）
ipset flush wardennet_blacklist

# 紧急解封单个 IP
wardennet blocklist del 203.0.113.100

# 临时关闭检测（不改 ipset）
sed -i 's/mode: block/mode: report/' /etc/wardennet/config.yaml
# 5 秒热重载后，Agent 正常评分但不封禁

# 完全停止 Agent + 清理所有防护
systemctl stop wardenet
iptables -S INPUT | grep wardennet | sed 's/-A/-D/' | while read cmd; do iptables $cmd; done
ipset destroy wardennet_blacklist 2>/dev/null
ipset destroy wardennet_whitelist 2>/dev/null

性能调优建议

场景建议配置
高 QPS 网站 增大 10s 窗口 max_req 到 50+；灵敏度设为 low；基线自学习自动追踪正常流量
API 服务器 空 Referer 已自动降级 80% + 硬上限；401 已降权 1/5 + 硬上限；okhttp/python-requests 等已知 HTTP 客户端自动豁免
内部系统 增大 sensitivity 阈值；在 known_http_clients.excludes 中添加确实合法的 UA（如 curl/wget）；在 sensitive_paths.excludes 排除业务路径
CDN 反向代理后端 将 CDN IP 段加入 ipset.whitelist（支持 CIDR 网段）
业务存在特殊路径 在 dangerous_patterns.excludes 中排除确实需要访问的路径（如文件下载功能含 ../）
云端威胁情报 设置 dangerous_patterns.disable_cloud: false 启用云端动态更新（需 CloudPlugin）
误杀排查 开启 debug 日志查看 detector score detail，关注 (mitigated) 标记和 (legmit) 降权是否生效
资源紧张服务器 增大 log.level 到 warn；禁用 stats.report_interval: 0；减少不必要的 log_sources

健康检查脚本

以下脚本可配合 crontab 或 Prometheus 进行定时健康检查：

Shell
#!/bin/bash
# wardennet-healthcheck.sh

SOCK="/var/run/wardennet.sock"
FAIL=0

check() { $2 && echo "✅ $1" || { echo "❌ $1"; FAIL=$((FAIL+1)); }; }

check "systemd 服务运行中"   "systemctl is-active --quiet wardenet"
check "UnixSocket 存在"       "[ -S $SOCK ]"
check "CLI 响应正常"          "wardennet status &/dev/null"
check "ipset blacklist 存在"  "ipset list wardennet_blacklist &/dev/null"
check "ipset whitelist 存在"  "ipset list wardennet_whitelist &/dev/null"
check "iptables DROP 规则"    "iptables -S INPUT | grep -q wardennet"

if [ $FAIL -gt 0 ]; then
  echo "FAIL: $FAIL checks failed"
  exit 1
else
  echo "OK: Agent 运行正常"
  exit 0
fi
crontab -e
# 每 5 分钟检查一次
*/5 * * * * /usr/local/bin/wardennet-healthcheck.sh >> /var/log/wardennet/health.log 2>&1
