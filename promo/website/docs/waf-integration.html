WardenNet 与商业 WAF 的协同关系

一、核心结论

WardenNet 与商业 WAF 是互补关系，不是替代关系。WardenNet 填补了商业 WAF 在行为分析、内核级处置和协同防御三个维度的空白。最专业的架构是「商业 WAF + WardenNet Agent」的串联防御体系。

二、先理解商业 WAF 的工作模式

商业 WAF（Web Application Firewall）本质是一种反向代理。流量路径决定了防护逻辑：

部署模式流量路径WAF 行为Nginx 日志可见 IP
串联模式 客户端 → 商业 WAF → 源站（Nginx） 所有请求经过 WAF 转发，WAF 拥有真实 IP 视角，转发时附带 X-Forwarded-For、CF-Connecting-IP 等 HTTP 头 $remote_addr 显示的是WAF 转发节点 IP，真实攻击者 IP 藏在请求头里
旁路模式 客户端 → 源站（Nginx）→ 旁路同步给 WAF WAF 只读流量（Mirror/旁路复制），主动发回拦截/放行指令给源站 $remote_addr 就是真实攻击者 IP，WAF 不介入流量路径

三、商业 WAF 的天然盲区

盲区原因WardenNet 如何填补
高频撞库 / 慢速 CC 单次请求完全合法，WAF 无法按特征匹配拦截，只能依赖硬编码阈值规则，极易误杀或漏杀 基线自学习引擎识别"行为形状异常"，多窗口（10s/30s/60s）联合评分，10 秒即可拉高分，无需预置阈值
扫描行为检测 Cloudflare/阿里云 WAF 偏重 URL/IP 威胁库和已知 Payload，缺乏路径模式分析和动作连贯性判断 Consistency 5 维 gate（前缀连贯、新颖度饱和、路径集中、状态同质、方法语义）精准区分扫描器和真人浏览者
集群打散型 CC 攻击者用数千僵尸机轮询同一接口，单节点 QPS 完全正常，WAF 的单节点视图无法察觉"分布式异常" WardenNet Cloud SaaS 多节点情报聚合，跨租户识别"分散式 CC"模式并触发协同封禁

内核级封禁（ipset/iptables） 商业 WAF 最多做到 HTTP 层 302/Block 或 Cookie 挑战，无法在内核层直接丢弃 SYN 包 Agent 直接操作 ipset + iptables DROP 规则，封禁瞬间生效，零用户态资源消耗，攻击者连 TCP 握手都无法完成

四、WAF 串联场景下 WardenNet 是否还有效？

完全有效——前提是你需要正确地从 HTTP 头里提取真实攻击者 IP。WardenNet Agent 的 Nginx 日志解析器支持真实 IP 提取，优先级如下：

真实 IP 提取优先级：
CF-Connecting-IP（Cloudflare 专用）> True-Client-IP（AWS/Cloudflare 通用）> X-Forwarded-For（取第一个 IP）> $remote_addr（兜底）

要让 WardenNet 拿到真实 IP，你需要在 Nginx log_format 里把真实 IP 写到 access log 里。以下是经过生产验证的标准配置：

Nginx
http {
    # ... 其他配置 ...

    # 真实 IP 提取的 log_format（WardenNet 需要这一种）
    log_format wardenet_real_ip '$remote_addr - $remote_user [$time_local] '
                                '"$request" $status $body_bytes_sent '
                                '"$http_referer" "$http_user_agent" '
                                'realip="$http_cf_connecting_ip$http_true_client_ip" '
                                'xff="$http_x_forwarded_for" host="$host"';

    server {
        listen 80;
        server_name your-domain.com;

        # 关键：用上面定义的 log_format
        access_log /var/log/nginx/access.log wardenet_real_ip;

        # 如果用 Cloudflare，强烈建议同时配置 set_real_ip_from
        # set_real_ip_from 173.245.48.0/20;   # Cloudflare IPv4
        # set_real_ip_from 2400:cb00::/32;   # Cloudflare IPv6
        # real_ip_header CF-Connecting-IP;

        location / {
            proxy_pass http://backend;
        }
    }
}
⚠️ 关键：Header 透传是前提
部署前务必验证真实 IP 头是否真的进入了源站。最简单的验证方法——在 Nginx 开启 debug 日志，或者临时加一个 server_name test-real-ip.your-domain.com，用 curl 带 X-Forwarded-For 请求，检查 access log 里对应字段。

如果你的 WAF 是 阿里云/腾讯云 WAF，它们的默认转发头叫 X-Real-IP 和 X-Forwarded-For。如果是 Cloudflare，推荐用原生的 CF-Connecting-IP（比 X-Forwarded-For 更干净，只含真实 IP）。如果是 AWS CloudFront，用 True-Client-IP。

五、WardenNet 旁路模式场景

如果你的部署链路中 没有商业 WAF（这是 WardenNet 的原生设计场景），事情就简单多了：

  • 客户端直接打到 Nginx，$remote_addr 就是真实攻击者 IP
  • Agent 无需任何 header 解析，直接读取标准 Nginx access log 即可
  • 检测和封禁能力完全不受影响

这种场景下 WardenNet 是你的唯一行为分析 + 内核级处置引擎。

八、常见误解澄清

Q1：我用了 Cloudflare（或阿里云 WAF），是不是就不需要 WardenNet 了？

不是。Cloudflare 是目前最强的 Cloud WAF 之一，但它的核心定位是已知威胁特征匹配 + 基础速率限制 + DDoS 流量清洗。对于你自己业务独有的扫描模式、撞库行为、慢速 CC、集群打散型攻击——这些 Cloudflare 的规则库根本不存在，只有行为异常检测才能捕获。WardenNet 就是在 WAF 之上补足这块盲区。两者不冲突，不重复，各管各的维度。

Q2：WAF 串联时 WardenNet 看不到攻击者的真实 IP？

错。只要 WAF 在转发请求时附带了真实 IP Header（CF-Connecting-IP / X-Forwarded-For / True-Client-IP），并且你在 Nginx 的 log_format 里把这个 Header 写进了 access log，WardenNet Agent 的解析器就能正确提取真实 IP。这是行业标准做法——Cloudflare、AWS、阿里云、腾讯云 WAF 都已支持。关键是部署前验证 Header 是否真的透传到了源站。

Q3：WardenNet 和 WAF 会"打架"，重复封禁同一个 IP？

不会。原因有三：

  1. 判定标准完全不同。WAF 看的是"这个请求长得像不像 SQLi/XSS"（特征匹配）；WardenNet 看的是"这个 IP 的整体行为形状是不是偏离了它的基线"（异常检测）。两者基于不同维度的信号决策，天然互补而非重叠。
  2. WardenNet 的封禁是内核级的。一旦某个 IP 被 WardenNet 加进了 ipset 黑名单，iptables 在 SYN 包层面直接丢弃，这个 IP 的请求根本到不了 Nginx，自然也不会再被 WAF 处理——不存在"重复"问题。
  3. 你可以控制白名单。如果你担心误杀 WAF 上游节点或 CDN 回源 IP，把它们加进 WardenNet 的 ipset.whitelist（CIDR 网段形式）即可。

Q4：商业 WAF 太贵，但开源脚本（fail2ban / Nginx limit_req）够用吧？

取决于你的风险承受能力，但坦白说：

  • fail2ban 的拦截规则全部是硬编码正则（例如"超过 5 次 401 就封 10 分钟"），稍有调参不慎就会误伤合法用户，对慢速 CC、撞库这种"单次合法、整体异常"的攻击完全无能为力。
  • Nginx limit_req 是 单 IP QPS 阈值，攻击者换 IP 就绕过，且无法识别"同一个攻击者控制 1000 个 IP"的集群打散型模式。
  • WardenNet 的基线自学习 + Consistency 5 维行为连贯性是 自适应的——你不需要为每个接口猜阈值，也不依赖威胁库更新。它比开源脚本聪明得多，也比商业 WAF 便宜得多（Agent 开源免费）。

九、一句话总结

商业 WAF 是你的门卫——它守在门口，检查每个人的身份证，拦截已知的坏家伙；
WardenNet 是你的神经中枢——它感知整栋楼的异常振动，分析行为模式的不正常，并可以直接切断攻击者的网络连接。
两者不在一个维度，是黄金搭档。
